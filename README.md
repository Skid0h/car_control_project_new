Краткое описание для поля About
Система ручного и автономного управления роботизированным автомобилем на NVIDIA Jetson Xavier и Arduino: распознавание конусов с YOLO, движение по размеченной трассе, удалённый пульт, видеотрансляция и запись заездов.

Car Control Project
Программный комплекс для управления роботизированным автомобилем в ручном и автономном режимах. Проект объединяет компьютерное зрение, построение целевых точек движения, управление двигателем и рулевым сервоприводом, а также удалённый мониторинг.

Архитектура разделена на три уровня:

NVIDIA Jetson Xavier — обработка изображения с камеры ZED, распознавание конусов, логика автономного движения и сетевой сервер.
Arduino — приём команд по последовательному порту и управление ESC двигателя и рулевым сервоприводом.
ПК оператора — графический пульт для управления автомобилем и отображения телеметрии.
Реализованные возможности
1. Компьютерное зрение и распознавание конусов
Получение видеопотока с камеры ZED через ZED SDK.
Детекция синих, жёлтых и оранжевых конусов с помощью Ultralytics YOLO.
Настройка порогов уверенности и IoU для фильтрации результатов.
Получение координат рамок, классов, уверенности и опорных точек обнаруженных объектов.
Выбор CUDA или CPU для инференса; в конфигурации указан файл модели формата TensorRT .engine.
Уменьшение разрешения и обрезка кадра перед детекцией для снижения вычислительной нагрузки.
Обработка кадров с заданной частотой с сохранением последних результатов между итерациями.
Использование CUDA-функций OpenCV для отдельных операций обработки изображения, если они доступны.
2. Автономное движение по конусной трассе
Оценка расстояния до конусов по площади их рамок в изображении.
Расчёт приблизительного бокового положения конусов с использованием параметров калибровки камеры.
Фильтрация объектов по допустимому диапазону расстояний.
Поиск пар синих и жёлтых конусов с учётом разницы по глубине и поперечного расстояния.
Построение целевых точек в серединах найденных пар.
При отсутствии пар — формирование виртуальных точек со смещением от одиночных конусов.
Приоритет точек от реальных пар: если найдена хотя бы одна пара, виртуальные точки не добавляются.
Выбор ближайшей целевой точки и расчёт рулевого управления по угловому отклонению от неё.
Остановка и отключение автоматического режима при приближении к оранжевому стоп-конусу.
3. Удалённое ручное управление
Для ПК реализован графический пульт на Pygame:

Движение вперёд и назад, повороты с клавиатуры.
Включение и отключение автономного режима.
Перехват управления оператором: ненулевая команда движения или поворота отключает автопилот.
Изменение настроек тяги вперёд и назад во время работы.
Запуск и остановка видеозаписи.
Отправка команд на Jetson по UDP с частотой 20 циклов в секунду.
Отдельно предусмотрен пример прямого управления Arduino с ПК через последовательный порт.

4. Обратная телеметрия
Jetson отправляет клиенту состояние системы в формате JSON:

Текущий режим: AUTO или MANUAL.
Состояние видеозаписи.
Статусы подключения камеры и Arduino.
Текущие настройки управляющего сигнала двигателя.
Системные сообщения, включая завершение заезда и результат перезапуска.
Пульт отображает режим работы, состояние камеры, запись, настройки тяги и наличие ответов от сервера. Статус Arduino передаётся сервером, но в основном интерфейсе клиента отдельно не выводится.

5. Управление исполнительными механизмами
Автоматический поиск Arduino по описанию USB-устройства и VID.
Передача команд по UART в формате <motor,steering>.
Преобразование нормализованных команд движения в значения импульса ESC.
Преобразование команды поворота в угол сервопривода.
Ограничение диапазонов управляющих значений.
Повторная отправка неизменившихся команд через заданный интервал.
Защита доступа к последовательному порту блокировкой между потоками.
В Arduino-скетче предусмотрены неблокирующий приём пакетов, проверка диапазонов и управление устройствами через библиотеку Servo.

6. Механизмы остановки и восстановления
В коде предусмотрены:

Отправка нейтральной команды при инициализации и закрытии подключения.
Программный watchdog для остановки при отсутствии команд в ручном режиме.
Failsafe на стороне Arduino: перевод двигателя в нейтраль при отсутствии корректных команд более 500 мс.
Попытка переподключения ZED после серии ошибок захвата кадров.
Серверная команда повторной инициализации Arduino и камеры без завершения основного процесса.
7. Видеотрансляция и запись заездов
Веб-сервер на Flask с MJPEG-трансляцией для просмотра в браузере.
Наложение на изображение рамок конусов, названий классов, линий пар, целевой точки и линии траектории.
Отображение режима работы, счётчика кадров, оценочного расстояния и индикатора записи.
Запись обработанных кадров в отдельном потоке через очередь.
Сохранение временного видео в MJPEG/AVI.
Фоновая конвертация в H.264/MP4 через FFmpeg после завершения записи.
Автоматическое формирование имён файлов с временными метками.
8. Централизованная конфигурация
Основные параметры вынесены в config.jsonc:

Сетевые адреса и порт.
Настройки последовательного соединения.
Нейтраль двигателя, тяга и диапазон рулевого управления.
Параметры камеры и модели YOLO.
Условия сопоставления конусов и построения целевых точек.
Порог остановки перед оранжевым конусом.
Параметры визуализации, записи и таймаутов.
Стек технологий
Python, C++ для Arduino, NVIDIA Jetson Xavier, CUDA, PyTorch, Ultralytics YOLO, TensorRT, OpenCV, ZED SDK, NumPy, Flask, Pygame, PySerial, UDP, FFmpeg.

Особенности текущей версии
Основной автопилот использует оценку расстояния по размеру конуса, а не карту глубины ZED. Работа с картой глубины показана в отдельных примерах.
Параметры PID и lookahead_distance присутствуют в конфигурации, но PID-регулятор и полноценный Pure Pursuit в основном алгоритме не задействованы.
Модель распознавания и датасет в архив не включены — путь к модели необходимо настроить отдельно.
Это экспериментальная система: наличие watchdog и failsafe не заменяет проверку поведения на оборудовании и независимую аварийную остановку.
